# Adaptive CardSpec：可组合体验、共享数据与双飞轮

状态：首版已实现，可选实验 profile `adaptive-v1`，当前 prompt `adaptive-v1.1`。保持 direct / experience / staged / DIL；本轮门控未通过，不替换默认。

## 本轮约定

- 简单请求最多 60 秒、3 次模型调用；复杂请求最多 300 秒、6 次模型调用。共享预算包含规划、工具后的续写、分析、修复和兄弟页；一次修复，不能通过拆分重置预算。首个完整、校验通过的原生卡才计 first usable。
- 已有 React sandbox 作为通用的视觉/局部交互扩展，不引入第二套 CardSpec DSL。native 模式独立完成任务；hybrid 才能生成增强，失败保留原生实现。工具权限始终在宿主；沙箱没有网络、DOM 或任意外部状态写权限。
- 工具数据保留完整原文、来源、覆盖度和版本。模型只读取有界样本；图表、筛选、原文使用同一个数据集。统计由宿主计算；模型分类必须逐条引用原记录和原文，不能把新闻标题当用户态度。
- 通用组合 explore / compare / planner / simulator 负责渐进披露、选择与空间策略；业务动作仍使用已有 action / binding / logic。不是五个案例专用模板。
- 生成前 workflow 只接受目录内的只读工具和通过校验的参数。依赖显式、无环；浏览器读取串行，公共读取最多两个并发。失败保留覆盖度，不把错误转换成“零结果”。
- 复杂内容采用现有 slot / 页面栈分段生成，每段完整校验后提交。深度错误本身不触发递归生成；保留稳定 ID 和原页面。持续生成需用户操作，不无限续写。

## RSI 两层记录

第一层比较契约、组合、prompt 与 harness 版本；第二层保留同题 H5、原生 CardSpec、hybrid 的产物与真实交互 trace，作为人审后的偏好/修复数据。训练资格沿用 `server/rsi-records.mjs`：同一产物 hash、六尺寸 QA、事实核验和人工批准缺一不可。不自动训练、不自动晋级默认。

## 验收与发布

先运行确定性数据/预算/事务/恢复与浏览器测试，再跑原 20 例及五基线、留出题。模型成功率、核心功能、视觉适配、真实数据可用性、first usable 与最终耗时分别报告。模拟数据与真实调用分开。视觉盲评保留人工步骤，不能用组件数冒充质量。

所有改动仅在本地 8787。维护 OpenCLI/Owl 原绑定；服务更新通过既有 handoff 机制完成。

## 使用入口与实现范围

- 主页面勾选“自适应体验（实验）”。“仅 CardSpec”仍独立完成任务；另选“CardSpec + React 沙箱”才允许增强。
- `/adaptive-review.html`：原流程、新流程、历史 HTML 对照，按产物 hash 留反馈、导出；此页禁用真实工具重放。五个 H5 基线仍在 `/h5-baseline/index.html`。
- `/adaptive-eval/report.html`：批次成绩、逐例失败、真实工具验证和未通过门控。原始 trace 在 `artifacts/adaptive-eval`、`artifacts/adaptive-eval-v2`，在线新请求记录在 `artifacts/rsi-adaptive/runs`。
- `workflow.run` 是只读、有显式依赖的 DAG；尚不自动推导输入映射或跨站等价回退。`dataset.analyze` 的引文校验证明引用来自原记录，不等于分类结论已经核实。
- 数据 checkpoint 保存 15 分钟，显式重试且目标一致时复用；不自动重放 GLM。复杂独立内容仍通过现有 slot/页面栈继续，不提供无限递归拆分。
- map 为真实坐标的位置示意，未提供街道底图或路径导航。日期聚合使用来源 ISO 日期，不擅自转换时区。
- React 在隔离 VM 执行，宿主渲染校验后的 UI 树；无网络、DOM 或工具权限。恢复时复用局部状态。窄屏越界会隔离增强视图，原生交互继续可用；手动重试才再次生成。

## 本轮证据（2026-10-20）

同一模型 glm-5.3-flash、方形、native、关闭工具的原 20 题；旧流程、初版压缩、修订版各一轮。另有 10 个明确使用模拟数据的基线方向与留出题；这不能替代真实来源验收。

| 一次修复后通过 | 19/20 | 19/20 | 18/20 |

修订版的两个原始失败是日历未选中日期和历史事件别名作用域。日历边界已通用修复，原生成文本可直接编译、选日、翻月；原始批次成绩没有回填。附加留出题还有表达式调用错误。首版过度精简降低了效率，因此恢复常用控件契约，只按需披露长尾能力。

- 353 项单元测试通过（受限并发，避免 50ms 隔离执行预算受到本机并行测试的竞争影响）。
- 新通用组件 30 项六尺寸交互检查通过；五个基线方向的真实生成产物，加日历边界复验，共 36 项通过。这些是程序行为检查，不是视觉盲评。
- 真实 `workflow.run`：Google News 与 B站各取得 3 项；继续读取 3 条用户评论并完成带原文的分类。无登录、绑定变更。
- 真实 GLM 生成前取数：96.1 秒，3 次模型调用、2 次读取；预取数据在卡内恢复，筛选与出处链接通过，交互不重复取数。模型实际选用 Google Search 与 B站 Search；Google 搜索结果不应自动等同于经过筛选的新闻事实。
- React 真实生成、VM 状态恢复、浏览器原生/增强切换已验证。首个样本有固定宽度；增加流式宽度与 SVG viewBox 约定，并验证越界回退。响应式修订样本仍有 SVG 位置绘制问题，属于模型视觉逻辑错误，不能仅凭状态数值变化计作完整成功。

## 下一道门控

本轮不宣称达到 H5 的完整视觉与业务质量，也没有证明整体延迟优于旧流程。优先继续：

1. 用当前失败 trace 修正作用域/表达式理解及来源语义；保留冻结对照，避免把复验混成首次成功。
2. 让体验规划稳定选用合适组合，验证图表与原文的对应关系；当前模型仍可能使用普通控件或平铺列表。
3. 检查 React 图形反馈是否与状态一致、是否重复处理键盘事件；不能把无横向溢出当作视觉正确。
4. 三轮固定基准、留出题语义验证与人工 H5 盲评后，再决定晋级默认。原生、hybrid 与 React 增强独立记分；未审查产物不得进入 post-training。
