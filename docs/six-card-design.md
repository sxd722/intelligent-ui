# 六卡风格与生成流程

## 本轮目标
参考用户提供的 six-cards-432.html，补齐 `parchment` 羊皮纸、`business` 专业商务、`academy` 辉石学院。保留 Pearl / Atlas / Persona 与默认样式；正常生成、样板和调试共用实现。仅本地 8787。

| 风格 | 构图与交互 | 可复用能力 |
|---|---|---|
| 羊皮纸 | 纸纹、朱红编号、蚀刻插画；前后章与视角切换 | collection 的 folio 表现，一次解释一个对象 |
| 商务 | 浅纸面、藏蓝数字、青色比例；切换统计区间保留对象 | chart 的 comparison 表现，共用正负尺度 |
| 辉石 | 深蓝尖拱、金色细节、三牌舞台；揭示后选择解释 | collection 的 spread 表现，状态驱动翻面 |

样板数据明确为示例；不复制参考文件的时效性市场数据，不声称塔罗能预测事实。普通 CardSpec 不依赖 Web，关闭动画仍完整可用。

## 六卡带来的启发
1. **先定一个任务和状态闭环，再选皮肤。** 参考中真正有用的是“选 token→数值变化”“选演出→行程”“换区间→同尺度比较”，不是组件多。
2. **给模型短选择，给宿主具体实现。** 模型选择 design、主体表达和数据绑定；宿主拥有构图、插画、裁切、动效和尺寸策略。新视觉先在 sandbox 探索，通过后才晋级原语。我们仍是 CardSpec 编译器＋渲染器，不假定已有通用 IR。
3. **先预算操作区，再预算正文。** 432/360/320 和自然高度共用信息层级；长文变为同卡章节或详情，而不是无限滚动。一次只保留一个解释所有者。
4. **运动必须服从状态。** 内容与选中状态立即正确，动画只是过渡；重复点击、恢复、减少动态和离屏暂停都不能改变业务结果。
5. **分开检查正确与好看。** DOM/计算/状态恢复作为硬门槛；构图、风格与探索价值由人工评价。截图只证明某一时刻，不证明完整动画或 HMOS 性能。
6. **双飞轮积累失败到修复的证据。** 保存需求、简短设计、DSL、宿主版本、前后截图和动作断言。一个循环改善契约/模块，另一个积累模型训练候选；未经人工确认不作金标，也不让生成器修改自己的验收标准。

## 实施和验收
先注册风格与短契约，再实现三个通用表现、样板和生成选择入口。测试三家族 × 六尺寸/模式，覆盖默认、选择、切换、揭示、恢复、减少动态；复查旧四家族。记录未通过项，不把示例自测当作真实模型首次成功率。未来按真实请求评估延迟后再决定是否增加规划调用，本轮不增加固定模型调用。

## 本轮观察
已接入三种 design、folio/spread 集合表现、comparison 共用刻度，以及正常生成选择入口。三次真实 GLM 请求均编译成功（32.7/14.5/25.0 秒；修补0/0/1次），但源码复查发现：章节卡重复外置翻页与说明，商务卡把区间写进对象ID、导致切换后选择不再对应。这不是模型“不会写风格”，而是缺少信息所有权和稳定对象身份的规划。已补两条短契约提示，尚未用新提示重跑模型，不能宣称问题已全部解决。

新样板数据与动作经过浏览器验证；真实模型产物只记录编译与源码复查，不冒充完整交互验收。卡牌插画是宿主装饰几何，未实现22张完整塔罗图库或随机占卜；市场数据是虚构。样板保留 candidate，后续应以用户视觉反馈及非模板任务共同验收。
