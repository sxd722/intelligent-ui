# CardSpec 快速能力索引与展示容错

2026-10-22 本地迭代。目标：让模型按任务定位能力，减少重复目录与猜测；让动态数据中的单行异常不破坏整组可用内容。

实现范围：CardSpec 生成增加任务到组件的速查表，以及 capability_find 只读检索工具；使用前仍由 component_describe/cli_describe 返回注册表中的精确契约。普通和自适应生成均可使用；工具地图压缩为领域、站点前缀、可用/不可用命令；不缩减真实工具范围，不增加强制规划调用。索引不授予权限，也不执行任何真实查询。

普通组件保持现有受控事件、binding、state、logic 与 sandbox 桥接方式，不新增另一套连接协议。原 staged、direct 和 DIL 兼容；非自适应 CardSpec 仍保留完整组件契约，并增加短索引；DIL 不变。

编译器仅接受两类保守恢复：bold→strong、italic→emphasis；忽略组件上固定字符串的 class/className，样式仍由宿主 token 控制。恢复记录 warning 和原始位置，不丢弃动作或改写表达式。动态 class 表达式、style、未知事件、无效工具、错误类型和引用仍报错。

渲染器按行隔离 each 的动态身份错误。缺失、非法、重复 ID 的行显示非交互错误占位，其余行保持原始稳定 ID 和交互；同键重复的所有行都停用，不任意保留第一条，也不补随机业务 ID。既有编译期重复身份门控不放松。

验证：索引覆盖所有组件和已注册可支持工具；任务检索不执行 CLI、禁用工具不可调用；编译归一化保持内容及动作；动态重复/缺失身份和恢复测试；原有契约、工具发现、局部恢复回归。本轮不实施 card_test 多轮调试环境，不发布 GPT Site。

验证结果：509/509 自动测试通过，本地 Vite 构建通过；隔离 Chrome 测试了 320/360/432px × square/auto 六组合，动态注入三条错误身份行后，正常行选择与相邻计数按钮仍有效，恢复数据后错误占位消失且计数保留，无横向溢出。测试没有调用真实 CLI，没有连接用户 Owl。证据位于 artifacts/capability-index-20261022/results.json 及对应截图，测试脚本为 scripts/qa-capability-index.mjs。

同一注册表生成的工具目录由 11811 字符降至 2975 字符（约减少 75%），组件速查表 679 字符。该数字仅描述索引长度，不代表整个 prompt 的缩减比例或真实模型成功率。本轮未执行真实 GLM 生成对照。
