# GLM 工具发现与按需展开

更新：2026-10-14。仅本地 8787，保留 DIL；不发布 GPT Site。

## 原因

原实现把正则筛选得到的少数工具当成模型可见目录，并固定加入四个 AutoCLI 资讯工具。对“杭州饭店推荐”“有什么值得听的”“安排周末出游”等表达，关键词匹配可能漏掉相关 OpenCLI 能力；规划只看到 ID，DSL 又总带 Hacker News 示例。生成校验还把这份短名单当成允许使用的全集。因此问题不只是 GLM 的偏好，而是发现、提示与校验链路共同限制了选择。

## 当前实现

- **完整能力地图**：从宿主真实工具目录生成，按来源和用途分组，披露命令、简短用途、当前连接条件及写操作标识。区分 ready 与 unavailable；ready 不承诺外部来源一定成功。未接入的命令不编造。
- **相关契约按需展开**：保留轻量关键词初筛，补齐餐饮、播客、出游表达；规划选出的真实工具 ID 优先展开完整参数和输出列。最多展开 18 个 OpenCLI 工具，并沿用 22,000 字符的契约预算。完整索引目前约 11.4K 字符，不向每轮塞入全部完整 Schema。
- **发现与授权分离**：模型可以选择能力地图中其他当前可用工具；发布前按真实契约与实际可用集合校验，不能把未展开误认为不允许。不可用工具仍不能绑定。
- **修复提供真实契约**：已有一次修复会补充实际选中工具的输入、输出契约。编译器新增 binding 字面对象输入的未知字段检查，避免参数拼错仅在点击后暴露；动态参数值仍由执行时校验。
- **跨阶段一致**：信息规划、交互规划、direct/staged 生成、后续 GLM 页面/slot 使用同一目录来源。删除固定 Hacker News 示例，按相关工具生成例子。没有增加固定规划调用，静态任务无需工具。
- **可诊断**：生成 metadata.tool_disclosure 记录展开列表、可用/不可用数量与索引长度。能力地图是说明，不是执行权限；写操作确认等宿主限制仍有效。

实现入口：shared/cardspec/tool-discovery.mjs、shared/cardspec/tools.mjs、server/cardspec/handler.mjs、server/tools/service.mjs。

## 验证与限制

自动测试 137/137 通过，新增发现测试 4/4，包括完整目录覆盖、不可用能力排除、自然语言筛选、规划后展开、短名单外选择、修复补充真实契约、调用次数不增加。生产构建通过。

真实模型 glm-5.3-flash 运行四例（scripts/evaluate-tool-discovery.mjs）：

| 场景 | 模式 | 最终源码选择 | 完整生成结果 |
|---|---|---|---|
| 杭州饭店推荐 | staged | dianping.search / shop | 一次修复后成功 |
| 通勤中文播客 | direct | apple-podcasts.search / episodes | 失败：一次修复后仍以业务 ID/标题作为列表 key，违反 rowKey 契约 |
| 杭州天气、目的地酒店 | staged | wttr.forecast、ctrip.hotel-suggest / hotel-search | 失败：编译预演执行了当前 disabled 的匹配按钮，空 query 被拒绝；源码还有 bindings.result 等错误，不能算通过 |
| 本地计数卡 | direct | 无工具 | 首次成功 |

工具方向选择四例符合预期，但完整卡片通过仅 2/4，首次通过 1/4。后两例不能因为发现正确就记为生成成功。天气预报和当前天气均是该场景允许的天气工具，测试不强制唯一命令。

原始 SSE、生成源码、披露列表和诊断保存在 artifacts/tool-discovery-qa/*.json，summary.json 分开记录 toolSelectionPassed 与完整成功。测试仅生成、编译卡片，不挂载卡片、不执行声明的 CLI；未验证饭店、播客、酒店外部数据服务是否成功。本轮未重跑原有 20 例，也未声称修复全部模型生成问题。

检查时注册目录 195 项，当前可用 178 项，数量随连接和启用状态改变。保持 Owl 原 daemon 与绑定 session，未导航或关闭其页面。
