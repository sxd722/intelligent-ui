# 验收与 RSI 证据

## 先测语义，再测皮肤

针对新场景写确定性计算/数据测试；不要仅检查按钮数量或源码关键字。参考项目测试 `tests/h5-baseline.test.mjs`、`h5-insights.test.mjs`、`sentiment-sources.test.mjs`。对已有共享模块的变更重跑相关测试，新模块补自己的边界用例。

每个案例检查 320/360/432px × square/auto：
- 完成一条核心多步任务，实际断言结果，不仅点击无报错。
- 返回/刷新保留表单、选择、阶段；换一个对象不会读到旧对象详情。
- 空结果、单条、长列表、缺图、超长文字、缺字段和部分工具失败。
- 同参数重复点击、取消、乱序返回、修改参数；未结束请求不得恢复重放。
- 主动作在卡内可达，无非预期横向溢出；自然模式有界，资料按需可达。
- 一个局部视图报错，其他区域及操作继续有效；状态恢复不会传播坏数据。

现有 `scripts/qa-h5-baseline-v2.mjs` 只覆盖硬编码五例，不能作为新例验收。它与 `scripts/qa-h5-baseline-v2-errors.mjs` 可参考设计新用例。浏览器交互只通过当前环境允许的工具/驱动进行，禁止连接现有用户 profile 或变更 Owl；若工具不可用，标明未实测而不是编造截图。

## 公平比较

冻结原版和候选版本，使用同一需求、尺寸与工具快照；实时连接另测。记录模型实际显示名，未知则 unknown；agent迭代耗时、工具等待、模型耗时分开，token 不可得时不估造。用户新增需求与旧共同需求分开评估。

评分沿用五基线口径：任务实用性30%、互动探索25%、视觉组织20%、信息可信度15%、稳定适配10%；每项0–5。总分 `Σ(单项分/5×权重)`，附证据与置信度。核心功能错误或虚构实时事实阻止晋级；编译通过不等于交互通过，交互通过不等于事实通过。未测试项写未测试，不凑分数。

## 最小交付记录

在案例产物目录保存 BRIEF.md、源码、任务相关测试、REVIEW.md，以及运行记录：

```json
{"caseId":"new-case","track":"h5-host","artifactHash":"实际源码哈希","parentHash":null,"producer":"trae-agent","model":"unknown","mode":"fixture","toolSnapshotHash":null,"checks":[],"screenshots":[],"trace":[],"feedback":[],"humanApproved":false,"trainingEligible":false}
```

这是记录形状示例，生成时填真实值。trace 保存工具 ID/脱敏参数/结果或快照路径/时间、请求 ID、取消、校验错误和实际动作；不记录密钥、cookie、私密浏览器资料。公开部署不携带本地用户 trace。

## 双飞轮改进

每条反馈绑定 `caseId + track + artifactHash`，分清模型生成、prompt/契约、宿主/harness、渲染器、外部数据源五类根因；提出最小可泛化修正，不能只给单个题目硬编码。

- DSL/prompt/harness 飞轮：保留失败样本 → 改一组明确假设 → 固定快照回归 → 再测未参与设计的新题。
- Post-training 数据飞轮：保存需求、规划、原始失败、修改差异、最终产物和可核验偏好。只有完成隐私/许可与人工质量审核的版本才可候选导出；默认不训练、不自动晋级。

这五例属于开发集，不能宣称独立泛化测试。后续新题也要记录是否参与了提示或实现优化。
