# 交互卡片基线生成

目标是让用户更快理解、选择、完成任务，产出可运行、可检查的体验；不是把查询结果排成一张长列表。Agent 自己编写、预览、调试产物，不以一次模型 API 出码替代 vibe coding。

## 先确定执行路径

读取当前工作区的 AGENTS.md / TASK.md，确认项目根、允许修改的目录、案例 ID、现有产物及 feedback。只加载下列相关参考，不把所有文档和工具目录一次放进上下文。

- 新增联网 H5 基线：默认复用宿主受控桥接的 React + Tailwind H5 路线，见 [项目接入](references/project-integration.md)。
- 原生 CardSpec 或禁止 Web：核心任务必须完整使用原生能力；按 [快速生成与调试](references/cardspec-generation.md) 先查索引，再读取所需组件契约。缺口记录为 DSL 缺陷，不偷偷切换 H5。
- CardSpec + sandbox：只将复杂动画/计算/特殊视觉放进 sandbox，简单控件留在原生层；遵循现有 bridge，不另造一套协议。
- 旧 `trae-html` 是离线对照，不能冒充带 OpenCLI 的 H5 基线。若工作区限制不允许接入宿主，先完成允许的离线实现和接入说明，明确真实工具尚未验证。

## 生成与返工流程

1. **先写短设计，再写代码。** 用 [设计模板](assets/BRIEF.template.md) 记录用户目标、完成标准、主视觉、状态流、工具依赖与缺失时的体验。新案例采用新 ID，不覆盖旧基线。返工先绑定反馈对应的版本，保留旧产物。
2. **按契约规划，按证据呈现。** 读取宿主 `GET /api/tools`，只提取相关工具的可用状态和输入输出契约。可先用符合契约的受控 fixture 规划布局和调试交互，不必等所有真实查询完成。真实查询用于核对字段、稳定 ID、空值、日期和来源；用返回 ID 请求详情，不猜工具名或结果字段。fixture 与真实结果分开标记，未取到的事实不能编造。见 [工具与证据](references/tools-and-evidence.md)。
3. **选择适合任务的体验。** 默认一个视觉主体、一个核心操作闭环：操作 → 可见结果 → 可核对依据。地图、图表、图片、阶段演示按语义选用，不按数量凑组件。参考 [五种体验配方](references/experience-recipes.md)，不照抄领域内容。
4. **先打通最小闭环，再增加表达。** 实现数据归一化、纯计算、选择/筛选、详情/返回、状态恢复；随后增强图片和动效。展示模式是“概览 → 当前选择 → 按需原文/原始输出”。原始 JSON 是可选调试/证据入口，不是默认详情页。
5. **有界二次生成。** 当摘要、分类或规划确有价值时调用已有 GLM 工具：传选中证据的短片段和 schema，校验引用，再由宿主计算统计。复杂任务分阶段按需生成，保留已有可用结果；不能不断递归生成直到碰巧成功。
6. **验证、修正、留证。** 按 [验收与 RSI](references/evaluation.md) 跑任务相关的单元/交互测试与六种尺寸。每轮记录失败原因与改动；默认最多五轮定向修复，同一阻塞重复两轮时保留证据、明确未完成，用户指定预算优先。不能通过删除核心功能或削弱测试获得通过。
7. **交付可继续迭代的版本。** 给出预览入口、版本/hash、真实工具与替身的分开结果、截图/trace、限制和反馈位置。使用 [评估模板](assets/REVIEW.template.md)。没有人工确认就不把产物标成训练金标，不自动训练或发布。

## 共同体验要求

## 交付门控（v2）

- H5 开始编码前读取 [宿主兼容与恢复](references/host-contract.md)，用实际预览宿主验证输入→事件→工具结果。编译或独立浏览器页面正常不代表生产沙箱正常。
- 每例交付 `acceptance.json`，按 [功能验收](references/functional-gates.md) 记录动作、预期、实际、截图及真实/替身来源。运行 `node .trae/skills/interactive-card-baseline/scripts/check-evidence.mjs acceptance.json` 检查证据完整性；脚本通过仅表示记录完整，不代替浏览器观察。
- 构建产物默认是 candidate。独立复验核心闭环、恢复和六尺寸后才可 accepted。作者自测不能直接晋级；失败、未测、外部阻塞分别记录。
- 每次修复先分类：源码/契约、运行时、测试定位/步骤、外部服务。定位失败先修测试，不消耗源码修复轮次，也不能算产品通过。504、限额、登录等保留原始错误与已通过产物，不靠重写 UI 解决。
- 长任务在 `PROGRESS.json` 保存当前案例、源码/构建版本、最后通过项、待测项和下一步。中断不是完成；全批次结束才能写完成结论。恢复前重读最新 skill 和进度，只继续未完成步骤；不要自动重放账号操作或工具请求。
- 持久状态同时包含领域选择和导航位置，使用版本与形状校验；加载中的请求不恢复重放。错误恢复提供返回安全视图，不能只有重复崩溃的重试。


- 432px 方形优先，验证 320/360/432px；自然高度仍是有界阅读，当前基线主视图约 620px、宿主上限 680px。依据任务调整，而非截断必要答案。所有关键动作留在卡内；长资料用分页、抽屉或阶段切换。
- 对照、趋势、空间和因果关系用可读结构表达；没有关系的数据不硬连图，没有可信数值不编统计。
- 图片承担识别/比较作用，背景不算内容可视化。真实实体优先真实来源图片；示意素材明确标注。图片失败仍可读、可选择。
- 色块、留白和层次区分区域，弱边框，克制动效；尊重 reduced-motion。风格可参考 v0 的清晰排版，但不把所有场景固定成同一配色或布局。
- 状态变化需要可见反馈；重复点击合并，取消/离页/参数变化后的旧响应不得覆盖新选择。失败保留上次成功内容与用户输入。

## 项目边界

默认仅本地 8787；保留 DIL。不要因此技能自动发布 GPT Site、启动批次、恢复轮询、更换 Trae 模型、重启服务或改变 OpenCLI/Owl 绑定。遇到登录/验证码/权限阻塞，保留现场并报告；不得绕过。Skill 说明流程，不授予新增工具、账号写入或购买权限。

示例调用：`用 interactive-card-baseline，为“周末露营装备与天气决策”做一个新联网 H5 基线。先写 BRIEF，复用现有工具桥，完成多步交互和六尺寸检查，保留 trace 与 feedback，不修改已有五例。`
