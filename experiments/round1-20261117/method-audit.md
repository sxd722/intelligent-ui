# 首批、校准与确认：独立方法审计

审计范围固定为首批 28 个登记槽位、4 个 r3 校准运行、12 个 r4 确认运行。共 **37 次实际主运行尝试**；不包含正在另行实施的 P2 pilot。仅离线读取已保存证据，没有读取封存留出题，没有模型、浏览器或 CLI 调用，没有产品修改。

结论：证据足以识别若干共性失败，并保留有价值的候选继续研究；**尚不能选出一套已跨任务、跨重复成立的默认架构**。最强的正面证据是简单查询稳定完成、若干对象分配产物可用、宿主状态/快照的确定性 fixture 成立。真实工具闭环仍有实体污染和功能缺失。

## 1. 分母必须分开

|批次|登记槽位|实际尝试|直接浏览器独立验收产物|通过完整业务＋布局门槛|说明|
|---|---:|---:|---:|---:|---|
|首批 r1/r2|28|21|13|2|7 个不适用；21 次中20次生成链结束、1次按协议中止。8次没有可作为本次独立完整验收的证据，不能算通过|
|r3 校准|4|4|4|0|新增主运行；不是免费重抽，也不是r1重复|
|r4 新确认|12|12|10|6|2次无可回放spec，按未交付失败留在分母；6次通过均来自同一简单负对照家族|

首批可以分别写“已独立测试产物 2/13”和“全部实际尝试获得独立通过产物 2/21”。7个NA应另列，不能当0分参与质量平均。`first-batch.json` 的 `2/28` 只能作为计划槽位交付覆盖，不应标成条件成功率。

首批2个独立通过产物是印刷分配的 H1 与 S2。**S2 原生成链为 failed，保留的是 unverifiedPreview，后续独立测试才证明该准确产物通过。**所以2/21不是生成器自带验收成功率，也不是首稿成功率，不能不加解释写“生成成功2次”。需要分别保留：生成链状态、保留版本身份、独立业务状态、布局状态、最终产品是否真正交付。

37次合并的8个通过产物跨不同修订、不同题和不同能力，不能形成一个“最佳配置8/37”或版本提升比率。原始首稿、修复后版本、独立重复和基础设施回放也不是同一个计量单位。

## 2. 硬门槛与证据层级

- 已有业务断言并非只看点击或state changed：设备资格及unknown、机器容量与分配、罐体守恒与暂停、原文实体/引用、每照片决定与未确认筛选均有独立关系依据。
- 布局是整卡门槛。印刷B1与照片H1第二次业务可成立，但有布局失败，不能用业务passed覆盖整体failed。
- H2初始SVG比例正确不证明动态通路；必须有真实业务转移后图形同态。本轮H2生成产物未取得该证据，确定性fixture的通过不能补到模型产物上。
- 列表未在初始视口内并不必然不可达。原始DOM报告会标记部分scroll区域的项目；应结合分页/滚动/命中路径判断。关键操作被挤出整卡和真实遮挡另有证据，不应统称裁切。
- 恢复相同状态不等于恢复正确状态。资料S1会持久保存错误实体的正文/URL；机械恢复通过不能抵消来源门槛失败。
- 已保存截图、source/context/snapshot hash使人工核对可追溯；跨iframe有效可见面积仍未充分计量。名义SVG面积不可宣传成主体有效面积改善。

## 4. 基线、预算与成本审计

工作区不是Git checkout，当前commit为null；镜像d9ea2fc不能替代当前HEAD。B0有归档；首批部分进程loaded source/runner准确身份缺失，详见 `provenance/README.md`。之后完整source/build归档不能倒填为之前进程身份。

r3引入共同校准及候选修订，r4继续修正故障注入。r3独立回放使用r4构建，生成build `4a0e36…` 与评估build `99af49…` 已分列；它是有说明的校准回放，不是完全同构建重放。旧错误与原验证均保留。

`budget-compliance.json`的37次审计中有3条明确偏差：

- 水罐B1 r1、S1 r1出现3个唯一CardSpec修复版本，超过2版上限，并有耗尽后继续请求。
- 设备V1 r2虽只含2个CardSpec修复版本，但额外不同提交文本和耗尽后继续请求违反停止规则。

这三条不能构成等预算胜出证据。相邻callback、重复源码、真实独立源码修复不是同一个指标；修复数量需沿用已做的去重原始输出审计。3条malformed DSML保留为模型/序列化失败，不通过删除它们“改善”限额结果。

冻结预算为8模型请求、2唯一源码修复、240秒、12外部读取。已知37次每条模型请求不超过8；已知最长116.185秒；被协议中止那条墙钟仍unknown，不能算0。外部读取上限的逐run审计并未由预算摘要完整给出，不能凭模型调用限额通过就推导读取限额也全部验证。

审计时较新的 `usage-audit.json`：首批137请求、已知2,069,847 tokens＋1次usage未知；校准24请求/404,539 tokens；确认66请求/814,592 tokens；合计227请求、3,288,978已知tokens。**旧first-batch.md写2,041,989，少27,858，属于汇总时点差异，最终必须统一截止时刻。**金额unknown，不报0；缓存输入也不能当免费。独立浏览器、离线工程时间与模型在线时间应分别记录，不能用大量离线努力掩盖线上成本。

wire记录的实际返回模型为 `deepseek-v4-1-flash-261017`。主生成请求常见temperature0.4/max_tokens8192/thinking disabled，路由请求为0.2/1000且指定task_route；所以不是全链所有调用同一个采样参数。请求层证据优先于旧脚本手写值。没有可核实模型seed，不宣称随机性已固定。

## 5. 真实OpenCLI到底验证到哪里

P0四次真实Wikipedia search/page读取建立固定快照；资料S1 r3另有三次actual live-read浏览器调用。后一证据对应exact source：真实查询变化确实使结果变化，首篇正文比snippet丰富，首次固定原文及URL正确，保存记录可恢复。没有新增独立真实请求。

同时已证实新对象沿用旧正文：Biofluorescence选择后没有对应page请求，“读取正文”因旧extract存在而消失。固定回放中实际固定后，标题新但正文/URL旧。live记录的`08-refresh`是截图标签，之前已有找不到刷新按钮的记录，并没有新请求，不能作为刷新成功。

本轮只有Wikipedia这一来源的两个能力；不代表190+/1000+目录召回、需登录网站可用、跨来源合并或多领域真实闭环。固定快照每查询4条、每主题仅一篇page：未采集其他标题不能当模型工具失败，也不能把小样本写成全量。首批limit不匹配静默落入DEBUG_MOCK_NOT_EVIDENCE导致的污染必须单列harness，不归模型。后续授权前缀回放保留范围/截断语义，不等于新增真实数据。

A慢B快、取消、空/失败模式与返回后的无旧实体污染尚未在完整真实生成产物上全面通过。替身写保护9项fixture成立，但未证明真实账号切换可检测或外部写exactly-once；没有真实写操作。详见 `p0-write.md`。

## 7. 最终结论需要明确欠账

1. 没有完成P3冻结留出及至少四个真实工具留出任务；封存题未读取。主报告只能称本轮筛选/校准/小批确认，不应按任务书第13条宣称整轮目标全部完成。
2. 截图配对入口可以交付，但尚无人盲评；吸引力、愿意保留、复用偏好和多样性价值均待验证。
3. 首稿完成率与第一个有用结果时间没有像最终产物一样完整独立复验；不能拿首个compile或首张截图时间替代。
4. 3D/WebGPU/无GPU回退不在本轮业务产物验证范围。WebGL探针通过仅为环境能力。
5. 有效主体面积、跨iframe命中及操作后的布局覆盖仍不完整；已测6布局为初始状态，432关键路径不能外推所有尺寸所有状态。
6. 无合格默认候选时可以保留基线并关闭分支，节省预算不是失败。若继续互补组合，需独立预登记并另算P2；不能把新处理收益追认到单因素。

推荐最终措辞：**当前已得到可复现的失败簇、有限的可用产物与工程能力证据；尚未得到跨家族稳定优于基线的默认组合。**下一轮应针对唯一播放状态、实体身份约束、未确认谓词语义或真实生效的空间策略选择一个最小因素，保持其余条件不动；不要同时加例子、加runtime、改布局后归因为prompt。
