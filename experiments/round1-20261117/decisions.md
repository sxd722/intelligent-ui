## 4. 模型、契约、宿主与验收器分别出了什么问题

- **模型业务/初始化：** 不完整的依赖撤销、未确认集合谓词错误、重复保存同一状态导致覆盖、来源/实体身份没有随选择一起更新。增加图形或按钮并不能解决。
- **模型契约使用：** 在 action 中写不受支持的嵌套 if；logic 事件名或播放条件不一致；列表结果缺稳定键。保留编译诊断与全部提交，不重抽覆盖。
- **宿主/实验 harness：** H1 v1 CSS 优先级；精确回放缺口被 synthetic 示例遮盖；故障注入与正常回放模式混淆；唯一源码修复计数不准确。共同校准后用新 revision 重跑，旧结果保留。
- **验收器：** 把 state 与 derived 混用、把部分对象当完整相等、按固定分页序号操作响应式布局，会错误拒绝正确实现。独立验收改定位/采集方式，但不改冻结业务预期，原错误断言和修订理由均保留。
- **外部服务：** 本轮真实 Wikipedia 读成功，不外推账号登录工具。未覆盖的工具/详情样本是环境或数据覆盖缺口，不自动归为模型失败。

三条原始运行存在预算协议偏差；首批部分已加载源码身份也有缺口。它们不具备等预算优胜资格。详见 `budget-compliance.json`、`provenance/README.md`、`method-audit.md`。

## 5. 真实工具与保存复用的准确边界

真实 OpenCLI 共 7 次网络读取证据：初始采集 4 次，未改源码的独立 UI 3 次。注册目录 199 项不等于 199 项执行成功。生成阶段的 2 次工具请求是固定回放，不另算真实读取。两种证据明确区分。

UI 实测：改变 query 后候选改变；首次详情取得正文；固定依据及刷新页面恢复成立。但第二对象仍显示旧正文/旧 URL，而且没有真实再取数的刷新操作。**真实工具可被调用和消费，完整可靠任务尚未通过。** `08-refresh` 截图名称不是调用回执。

写操作仅隔离替身：未确认零执行、参数/目标改变票据失效、同 requestId 去重、断线 unknown 与恢复不盲重试，9 项通过。没有真实写、没有真实账号切换检测或外部 exactly-once 证明。

保存/复用已测到精确卡片的选择、分配、查询和记录恢复；它不代表真人长期复用。匿名配对可操作、可导出意见，但 humanPreference 仍为 null。3D 材质、WebGPU、跨 iframe 全状态可见面积、所有尺寸的完整业务路径也未全面验证。

## 6. 下一轮最小实验

优先研究 **“机制匹配的可执行例子能否减少跨状态关系错误”**，而非同时增加布局、运行时和新组件。

建议 3 个全新结构、两条件、各两次，共 12 次起始运行：

1. 只有一个状态所有者的多步更新；
2. 查询→实体→详情/记录的身份一致性；
3. 现有业务时钟的开始/暂停/单步与恢复。

两条件保持模型、运行时、能力清单、布局、预算完全相同；处理臂仅给一个运行时已通过的机制微例，对照给相同契约不加例子。例子不用测试题数据，不新增时钟或求解器，不同时引入 H2。预先记录适用条件和失败反例，核对实际披露与原始源码采用，再做独立路径验收。

晋级要求至少两个结构在重复中降低同类错误、无新增核心退化；未达到则关闭，不自动追加 prompt。C1 要另做采用率实验，V1 要另做同初稿配对，不能混进这 12 次。以上是下一轮最小方案，**本轮未自动启动**。
